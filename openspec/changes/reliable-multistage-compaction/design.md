# Design

## Context

See proposal.md and specs/reliable-compaction/spec.md. The fork now requires Pi 0.87.1+ because 0.84.3 did not export `buildSessionProjection`. Pi 0.87.1 preserves raw entries in its append-only session branch but projects only the newest compaction, kept messages, and subsequent tail into model context. V2 writes an opaque checkpoint plus a placeholder summary. The extension's `before_provider_request` return value can replace a payload, but handler exceptions are reported and ignored; `ctx.abort()` aborts the agent signal through Session.abort. Cache warming does not use that payload hook. Pi exposes `buildSessionProjection`, `generateSummaryWithUsage`, and `CompactionResult.usage`; its extension context exposes only a read-only session manager.

## Goals / Non-Goals

**Goals:** Preserve native quality when possible; avoid extra text calls for sessions that never actually request an incompatible model; never send a placeholder as a valid historical summary; maintain branch/reload safety and observable usage; make all tests provider-free.

**Non-Goals:** New native provider strategies (including Anthropic beta), changing Pi core or provider SDKs, calling real accounts in tests, guessing raw prompt details absent from a persisted session, weakening a passing quality gate, or claiming lazy portable usage is part of Pi session totals without a public write API.

## Decisions

1. **Separate creation fallback from later portability.** Keep the existing `compactionModel` as the first text fallback for compatibility and add `additionalCompactionModels: string[]` for ordered later candidates. Native success returns immediately. For native failure, try distinct configured models sequentially; abort stops the chain; after all non-abort failures return `undefined` so Pi runs its default compaction on the still-full pre-compaction context. Validate malformed entries without silently replacing the entire list. The installed config keeps its Kimi K3 model and initially has an empty additional list.
2. **Lazy portable summary at the context boundary, not model selection.** A `context` handler sees the active branch and target model before provider serialization. Only if the latest compaction is native, its visible summary is a placeholder, and the target cannot replay its identity does the handler generate a portable summary. It substitutes a `compactionSummary` of the same role in the current request. The summary is stored in a custom session entry tied to the native compaction entry ID; it is branch-sensitive, survives reload, and does not supersede the native compaction. Switching back before a request does nothing. Native-model requests never change their summary projection, preserving replay parity.
3. **Rebuild the *projected* hidden branch, not the raw unfiltered bytes.** Use Pi's exported `buildSessionProjection` on an in-memory branch with native compaction boundary entries omitted and parent links repaired; keep a prior non-native textual compaction as an authoritative base if one exists. Preserve IDs so `context_edit` replacements/omissions apply with Pi's last-wins semantics. Select only the source prefix hidden by the latest native checkpoint, excluding the kept/tail region already sent separately. Retain-none (`firstKeptEntryId === compaction.id`) has a dedicated boundary case. The existing V2 live-tail serializer also needs to project context edits before building new blobs.
4. **Bound the lazy work without truncating silently.** Estimate serialized message tokens against each candidate model's context window minus a response reserve. Summarize contiguous message chunks with Pi's exported summary helper, folding each prior chunk summary into the next. Never skip or truncate a source chunk; if one chunk cannot fit or a summary stops early/empty, abandon that candidate and retry the whole source with the next configured candidate. Last, try the active model using Pi's summarization helper (the on-demand analogue of Pi-default compaction). If every candidate fails or the branch cannot be projected, call `ctx.abort()`, notify the user, and keep the native checkpoint for retry/switch-back. A provider-free real-transport loopback test must prove that abort prevents the first incompatible HTTP request before this path can be merged.
5. **Block bypass routes.** `cache_warming_decision` stops warm requests to incompatible models while a native checkpoint has no portable summary. On a supported native provider, `before_provider_request` rewrite failure or unresolved native environment must abort instead of silently sending Pi's placeholder. When the portable summary is present, incompatible provider requests may proceed with the substituted text.
6. **Record usage without fabricating costs.** Convert valid Responses token usage (including cache tokens when provided) to Pi `Usage` and call Pi-AI's public `calculateCost` with the resolved model. Attach native V1/V2 usage to `CompactionResult.usage`. An on-demand summary's per-model usage is saved beside its custom summary for audit, but Pi's read-only extension session API does not expose `appendUsage`; do not cast around this boundary or claim it appears in `/session` totals. Keep this discrepancy explicit in docs and a later upstream Pi API request.
7. **Keep medium-priority gates separate.** After the high-priority PR is merged and installed, tighten V2 retry classification, move the smoke test to an offline provider-free path, and add CI. Replace the presently impossible all-files-100% coverage check with an owner-reviewed, baseline-pinned non-regression floor plus focused new-code coverage; do not describe it as full coverage. This gate-policy change remains a separately reviewed PR.

## Risks / Trade-offs

- **Long hidden history** → Chunked summarization can cost and take much longer on the first incompatible request. Abort leaves the session usable on the native model; no unbounded single model call or silent drop.
- **Native checkpoint is opaque** → Reconstructing from raw Pi entries cannot recover state that was never persisted in the session; report this inherent limitation. Tests cover two native compactions, prior non-native summary, forks, retain-none, and context edits.
- **Async hook and abort semantics** → Pi reports and continues after handler exceptions, so every failure path must abort explicitly. Test TUI/headless or equivalent binding and a localhost HTTP server with zero received requests; if the gate fails, stop rather than ship a placeholder leak.
- **Prompt cache warming** → Stop warming on pending portability; re-enable on supported native or after summary creation.
- **Portability summary accuracy** → Text cannot guarantee parity with encrypted state. Keep native replay when available, and expose that cross-model continuation is a lossy textual fallback.
- **Usage limitations** → Native usage enters Pi totals; lazy usage stays in extension evidence until Pi exposes a public usage-append API.

## Migration Plan

1. Raise the fork peer requirement to Pi 0.87.1+, then add the high-priority spec, characterization tests, implementation, and independent Kimi K3 review in an isolated worktree. Run offline tests and the abort loopback gate; merge into fork main only if no blocker, then pin the local Pi package to the exact merge SHA.
2. Base the medium-priority worktree on the fresh fork main; repeat tests/review/PR/merge/install. Keep upstream PR #7 and npm publication outside this initiative.
3. Rollback is not a blind global repin: the older `af0af24aef85a398872a5ffb50de7fbecdfc84d5` version lacks the opaque-placeholder guard. Only repin for sessions without a dependent native checkpoint, or after verifying a durable portable continuation; otherwise keep this version for that session or stop it. Never rewrite session files or another user's work as part of rollback.
