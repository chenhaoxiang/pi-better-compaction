# Read-only compaction diagnostics

`/compaction-status` reports the latest active-branch checkpoint kind, whether an opaque checkpoint has a digest-matching cached portable summary, up to 12 compaction-response / local replay-guard observations and token observations. `/compaction-status usage` shows only usage. Commands never resolve authentication, send model requests, prepare a portable summary, mutate checkpoints, or certify switch safety. Model/API/endpoint compatibility and raw-history safety are revalidated only on the actual request. No summary, blob, URL, credential or raw error is emitted. Returned response-ok is not proof of persisted checkpoint success. A `Native replay guard: failed (...)` observation means local replay alignment rejected the request before sending; it does not indicate a provider response or a summarization call. Replay reasons use the same closed-label sanitization and bounded runtime storage. Runtime observations reset at session start or tree navigation. In fork.6, metadata-only native V2 observations can additionally be restored from the active branch as described below; other absent historical observations remain unknown. Reason labels use a closed allowlist, with unknown reasons shown as unclassified.

Usage is read only from active branch entries. CompactionEntry usage is already accounted by Pi; lazy custom portable-summary and failed portable-usage entries are separate observations not included in `/session` through the existing extension API. Nested usageRecords on a compaction entry are not added again. Duplicate entry IDs are counted once; omitted/unusable observations are reported, not zero-filled. Counts are partial provider-reported token observations, not estimates of missing calls or a complete bill. Cost remains unpriced/unknown rather than pretending configured zero price means free.

Native replay recognizes the exact request-time `pi_subagents_notice` provenance envelope for raw `subagent-*` / `subagent_*` custom messages. The raw body, customType, block/image order, envelope metadata and serialized item count remain exact; arbitrary rewrites and omissions still reject. The actual provider tail is preserved, kept history is not duplicated, and persisted checkpoints are never changed. Recognition is an in-memory parity alternative, not another provider or portable-summary request. Synthetic tests compare the real Pi converter and exercise the production loader, a separate provenance handler, the replay hook and a loopback HTTP endpoint in both extension load orders. The old implementation sends zero loopback requests and aborts; the fixed implementation sends exactly one request with the opaque checkpoint and annotated tail, while the stored checkpoint stays intact. No private session or real provider is used by these tests.

## Native V2 transport recovery (fork.6)

The existing 600-second native V2 deadline remains operation-wide across bounded native retries. `deadline-exceeded` and optional `idle-timeout` enter the existing safe text fallback; an explicit caller cancellation remains `aborted` and stops the chain. The optional `nativeV2IdleTimeoutMs` accepts integer 0–600000 ms and defaults to 0 (disabled), avoiding an unapproved shorter limit on valid silent native compactions. V1, Anthropic, portable/text model budgets and global Pi settings are unchanged.

The read path also settles if a fetch or pending reader does not acknowledge cancellation; a terminal event does not wait for the reader cancellation promise. This is local closure, not proof that upstream work or billing was rolled back. An announced/received compaction output without `response.completed` remains incomplete, is never persisted as a checkpoint, and cannot issue another native POST. `[DONE]` without completion and `response.incomplete` terminate immediately as incomplete responses. Recoverable pre-output stream interruptions retain the existing bounded native retry policy.

Status and `/compaction-status` expose only closed stage/event labels, native attempt number, elapsed/idle/first-byte time, received-byte/event counts and an output-present flag. UI refresh is at most once per second when waiting; data-bearing stage transitions may refresh immediately. A live operation is not represented as successful, nor is a returned native response proof of checkpoint persistence.

One `pi-better-compaction-native-attempt` custom entry per returned native V2 operation retains schema version 1, method, response outcome, closed failure reason, trigger (`manual`/`threshold`/`overflow`) and transport counts/times. It is context-invisible and does not alter existing checkpoints, message history or token accounting. The command validates/reprojects its fields and exposes at most twelve active-branch observations after reload; it does not replay model requests. No prompt, tool output, URL, credential, response identifier, blob or raw error is persisted by this diagnostic path, even with debug disabled. Optional full debug payload logging remains separate and potentially sensitive. Storage/UI failures cannot decide fallback.

Synthetic tests cover silent headers/body waits, caller abort, deadline/idle classification, partial output without retry, missing completion, slow cancellation acknowledgement, progress cleanup, all automatic/manual trigger reasons, metadata-only persistence, and opaque-history recovery/fail-closed behavior. Real-provider acceptance and the original intermittent incidents remain unverified.

Native-first ordering, unsafe-history cancellation, chunk order and checkpoint persistence remain unchanged. Fork.6 distinguishes V2 transport expiry from caller cancellation as described below. The baseline 274 tests passed before changes; all existing assertions remain. New synthetic tests exercise checkpoint kinds, usage separation/invalid counts/duplicates, read-only commands and sanitized failures; regression, baseline coverage and changed-line coverage are required. Real-provider compaction, billing and live TUI/old-session activation remain separate acceptance.
